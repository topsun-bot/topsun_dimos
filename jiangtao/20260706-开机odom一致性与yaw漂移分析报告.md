# 开机 odom 一致性与 yaw 漂移分析报告

> 写给：在同一物理位置、站定不动、多次启动后发现「固定 T 重定位结果不一致」的排查。
> 数据目录：`jiangtao/cache/boot_consistency/`
> 记录脚本：`jiangtao/scripts/record_boot_consistency.py`
> 分析时间：2026-07-06

---

## 1. 一句话结论

**不是「每次开机随机抽一个 odom 原点」为主因，而是：Unitree 给出的 odom/world 在站定时，yaw 以约 `+0.31°/s` 近似恒速漂。**

因此：

| 现象 | 解释 |
|------|------|
| 隔几分钟再看 odom yaw 差几十度 | 时间 × 漂速，可预测 |
| 固定 `T_map_world` 过几分钟就偏 | world 系相对物理房间在转 |
| lidar 在 **base** 系差不多，**world** 差很大 | 传感器本身稳定，变的是 world/odom 朝向 |
| global_map 跟着转 | 建图直接累加 world 系点云 |

---

## 二、odom 是怎么来的？

### 2.1 数据链路

```
Unitree 机载栈
  └─ WebRTC topic: rt/utlidar/robot_pose   (原始 header.frame_id 常为 "odom")
        │
        ▼
dimos: UnitreeWebRTCConnection.raw_odom_stream()
        │  Odometry.from_msg()
        │  ※ 强制改写 frame_id = "world"（不是重新算位姿，只是改名）
        ▼
LCM /odom  +  TF world → base_link
```

关键代码：

| 步骤 | 文件 | 行为 |
|------|------|------|
| 订阅 | `dimos/robot/unitree/connection.py` | `RTC_TOPIC["ROBOTODOM"]` → `raw_odom_stream` |
| 解析 | `dimos/robot/unitree/type/odometry.py` | `Odometry.from_msg`：读 position / quaternion，**`frame_id="world"`** |
| 发布 | `GO2Connection` | `odom_stream` → TF `world→base_link`，并作为 `/odom` |

原始消息样例（仓库内注释样例）topic 为 `rt/utlidar/robot_pose`，header 里 `frame_id` 常为 `"odom"`。dimos **没有**自己做腿式里程计或 IMU 积分，只是把机上结果接进来并改名为 `world`。

### 2.2 lidar 也在同一套 world 里

`pointcloud2_from_webrtc_lidar` 把 WebRTC 点云直接标成 `frame_id="world"`。
也就是说：**机上已经把点云变到与 robot_pose 同一套 odom/world 系**，dimos 侧 `VoxelGridMapper` 再按 world 累成 `global_map`。

```
机上 lidar（已在 odom/world）──► VoxelGridMapper ──→ global_map (world)
机上 robot_pose ──────────────→ /odom + TF world→base
```

**含义**：odom yaw 漂 → 同一物理场景的 lidar 在 world 里也会跟着转 → global_map 跟着转。本次数据已验证这一点。

### 2.3 本次记录方式

| 模式 | 命令要点 | 有什么 |
|------|------|--------|
| `lcm` | blueprint 已跑，再 `record --mode lcm` | `/odom` `/tf` `/lidar` `/global_map` |
| `webrtc` | 单独连狗，不与 blueprint 抢 WebRTC | 原始 odom（`frame_id=odom`）、IMU rpy、lidar |

### 3.2 三次 LCM：odom_first（站定）

| run | position (m) | yaw (°) | 相对第一次 Δyaw |
|-----|--------------|------------|----------------|
| 205546 | `[-0.032, 0.006, 0.307]` | **-21.95** | 0 |
| 205822 | `[-0.027, -0.007, 0.306]` | **+28.29** | **+50.25°** |
| 210058 | `[-0.012, -0.012, 0.307]` | **+78.76** | **+100.7°** |

- 位置跨 run 差约 **1–3 cm** → 平移原点基本稳定。
- **yaw 差几十到一百度** → 问题在朝向。

### 3.3 单次 25s 内（站定）

| run | 位置 ptp (m) | yaw 漂移 (25s) | 漂速 |
|-----|------------|---------------|------|
| 205546 | ~0.002 | **+7.72°** | **+0.311 °/s** |
| 205822 | ~0.003 m | +7.75° | +0.310 °/s |
| 210058 | ~0.003 | +7.55° | +0.303 °/s |

三次漂速几乎一样 → **系统性偏差**，不是噪声抖动。

### 3.4 跨 run：时间 × 漂速 ≈ 实测 yaw

用第一次 LCM 测得的 `+0.3112 °/s` 预测后续：

| run | 距第一次 Δt | 预测 yaw | 实测 yaw | 误差 |
|-----|---------|----------|----------|------|
| 205546 | 0 s | -21.95° | -21.95° | 0 |
| 205628_webrtc | 42.1 s | -8.84° | -8.92° | **-0.08°** |
| 205822 | 155.6 s | +26.48° | +28.29° | +1.81° |
| 210058 | 312.1 s | +75.18° | +78.76° | +3.58° |

**误差只有 0～几度** → 更像「同一条 odom 在站定时以近似恒定角速度转」，而不是「每次冷启动随机抽原点」。

> 若你中间有真正断电/重启狗，仍可能叠加「重启后初值不同」；但就本批时间戳而言，**持续漂移已足够解释三次结果不一致**。

### 3.5 lidar / global_map 几何

相对第一次 LCM：

| 对比 | Δyaw | \|Δ world centroid\| | 用 Δyaw 旋转后残差 \|R_err\| | \|Δ base\| | \|Δ global_map\| |
|------|------|----------------------|---------------------------|----------|------------------|
| 205822 | +50° | **1.19 m** | **0.06 m** | 0.06 m | **1.17 m** |
| 210058 | +101° | **2.16 m** | **0.14 m** | 0.15 m | **2.13 m** |

解读：

- world / global_map 差大 → 固定 T 视觉上会偏。
- **用 odom yaw 差旋转后几乎对齐** → 房间没变，是 world 系在转。
- base 系差 6～15 cm → 机体系单帧大致稳定。

### 3.6 WebRTC / IMU 摘录（205628）

- odom：`frame_id=odom`，yaw ≈ -8.92°（与按时间预测一致）。
- IMU（lowstate）首帧：`yaw_deg ≈ 11.5°`（与 odom yaw **不是同一零点**，不能直接当 odom 的绝对值；可看相对变化）。
- foot_force 非零 → 站立承重正常。

## 四、`+0.31°/s` 正常吗？为什么会稳定漂？

### 4.1 正不正常？

| 场景 | 期望 | 本次 |
|------|------|------|
| 好的视觉/激光里程计，站定 25s | yaw 变化 ≪ 1° | **~7.7°** |
| 纯 IMU 未标定、无零偏估计 | 可能有恒定角速度偏置 | 符合「恒速漂」形态 |
| 导航可用的 odom | 站定几乎不转 | **不正常 / 不可接受** |

**结论：对「要做全局图 + 固定外参 / 跨时间重定位」来说，这不正常。**
对「Unitree 默认 leg+IMU 类 odom、没有强闭环」来说，**出现恒定 yaw 偏置很常见**，只是 **0.31°/s 偏大**（约 **18.6°/min**，**5 min ≈ 93°**）。

### 4.2 为什么会「稳定以一个速度」漂？

直观模型：

```
测得角速度 ω_meas = ω_true + b + noise
站定时 ω_true ≈ 0
→ 积分后 yaw(t) ≈ yaw0 + b · t
```

- **`b`（gyro bias / 航向零偏）在短时间（几分钟）内近似常数** → 看起来像「匀速转」。
- 位置几乎不动：平移用腿式/其他约束还压得住；**航向对偏置最敏感**，站定时没有「墙角闭环」把 yaw 拉回来。
- Unitree 的 `robot_pose` 与 world 系 lidar 同源 → 漂的是**整套坐标系**，不是 dimos 单独算错。

dimos **没有**在中间再积分一遍 IMU；漂来自**机上给出的 pose**。

## 五、那 global 建图 5 分钟后，图是不是完全对不上了？

要分三种「对不上」：

### 5.1 同一次启动、一直在建图（global_map 自己）

| 情况 | 会怎样 |
|------|---------|
| **站定建图** | lidar 已在 world；odom yaw 漂 → 同一堵墙在 map 里会**慢慢转/糊**。5 min 量级可到 **~90°** 量级的朝向差（按 0.31°/s）。 |
| **边走边建** | 点云与 pose 仍在**同一套漂着的 world** 里，**相对自洽**往往还行（导航在本会话内还能用）。但相对**真实房间朝向**会漂；长时间还会有缓慢旋转畸变。 |

所以：

- **不是**「5 分钟后地图突然随机炸开」。
- **是**「整张图挂在一个在转的 world 上」——相对物理北/上次建的图，会差几十度。

### 5.2 和「上次建的 premap / 固定 T」比

这才是你固定 T 实验里最痛的：

```
t=0:  估出 T_map_world，premap 与当时 global_map 对齐
t+5min: world 已相对物理空间转了 ~90°
        仍用旧 T → premap 与当前 global_map 差几十度 → 「完全对不上」
```

**固定 T 假设「world 相对 map 不变」；实际 Unitree world 在站定时都在转 → 假设不成立。**

### 5.3 和「绝对房间」比

- 5 min 后 odom yaw 可差 **~90°**（按本次漂速）。
- 若用该 world 存图、下次再来对齐，**朝向会对不上**，需要重新做 global 重定位（RANSAC+ICP），不能死用旧 T。

### 5.4 一张示意

```text
物理房间（固定）
      │
      │  理想：world 与房间固定
      │
      ▼
  world / odom  ←── 站定时 yaw ≈ yaw0 + 0.31°/s · t
      │
      ├── /odom、TF world→base
      ├── lidar (已是 world)
      └──► VoxelGridMapper → global_map

t=0 建的图 与  t+5min 的 live map：
  在 world 坐标里会差一个大旋转（本次量级：~90°/5min）
```

## 六、对重定位 / 固定 T 的产品含义

1. **不要假设 odom 原点/朝向跨分钟稳定**；站定也会漂。
2. **固定 T 只适合「同一会话、短时间」**；跨分钟、跨重启都应重新估 T（global 或至少带验收的 ICP）。
3. **global_map 与 odom 同源**，global_map 差大往往是 odom 漂的连锁，不是单独「建图坏了」。
4. 若要长期稳定 map：需要 **闭环 / 外部定位 / 不用机上裸 odom 当绝对世界**（例如以 map 为权威，持续估计 `world←map`）。

## 七、复现与复现命令

```bash
# 终端 A：blueprint 已启动，狗站定
# 终端 B
.venv/bin/python jiangtao/scripts/record_boot_consistency.py record \
  --mode lcm --duration 25 --tag boot1

# 对比
.venv/bin/python jiangtao/scripts/record_boot_consistency.py compare \
  jiangtao/cache/boot_consistency/boot1_20260706-205546_lcm \
  jiangtao/cache/boot_consistency/boot1_20260706-205822_lcm \
  jiangtao/cache/boot_consistency/boot1_20260706-210058_lcm
```

建议补做（区分「冷启动重置」vs「持续漂」）：

1. **真冷启动**：关机重启狗 → 立刻 record → 再关机重启 → 立刻 record。
2. **同会话长录**：不重启，站定录 2～3 分钟，确认 yaw 是否线性漂（本批已强烈支持）。
