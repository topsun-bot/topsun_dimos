# Go2 4G 远程 WebRTC 完整测试与 DimOS 接入指南

日期：2026-07-20
适用：Unitree Go2 Pro + DimOS（本仓库）
材料目录：`jiangtao/test/4G-WebRTC-test/`

---

## 一、最终结论（先看这里）

本机 ThinkBook（Linux）已验证：**电脑可保持 Clash 系统代理上网，同时经 Unitree 云信令 + TURN 用 4G 控制 Go2**，并拿到导航所需数据。

| 能力 | 结果 | 说明 |
|---|---|---|
| 建连 | 通过 | `robot_network_mode=4G`，约 1～2 s |
| 控制 | 通过 | StandUp / BalanceStand / StandDown，`code=0`，现场可见动作 |
| 状态 / 里程计 | 通过 | lowstate ≈ 20 Hz，odom ≈ 18 Hz |
| 相机 | 通过 | WebRTC Video ≈ 14 Hz，640×360 |
| WebRTC 点云 | 通过 | `voxel_map_compressed` ≈ 7～9 Hz，单帧约 2 万点 |
| DimOS `unitree-go2` | 通过 | LCM 上 lidar/odom/image/global_map 均有输出 |

> **关键点**：DimOS 导航用的就是 Go2 WebRTC 压缩体素点云（不是必须外接 Mid360）。4G 上点云可以通，前提是 `disableTrafficSaving(True)` + `ULIDAR_SWITCH=on` + 正确订阅。

LAN（`--robot-ip` / LocalSTA）默认路径**未改**。只有显式 `unitree_webrtc_method=remote` 才走 4G。

## 二、问题梳理：踩过哪些坑

### 2.1 现象

| 阶段 | 现象 |
|---|---|
| Mac 早期 | 偶发建连成功，多次快断快连后 Peer 一直 `connecting`，DataChannel 超时 |
| Linux + Clash | 云登录 / SDP / ICE `completed` 都正常，但完整 A/V offer 经常 DTLS 失败 |
| 误判 1 | 以为必须退出 Clash；实际 **Clash 可保持**，根因不是 HTTP 代理 |
| 误判 2 | 早期抓包点云为 0，曾以为「4G 不推点云」；后来按 DimOS 同款开关复测，**点云有** |
| 误判 3 | 外部 `LCMTransport` 探针收不到帧，误以为 blueprint 没发布；用 **原生 LCM `subscribe('.*')`** 可看到全量话题 |

### 2.2 根因与修复

```text
官方 unitree-webrtc-connect
  createOffer = audio + video + datachannel（三条 m-line）
        │
        ▼
aiortc / aioice 默认给每条 m-line 不同的 ice-ufrag / ice-pwd
        │
        ▼
经 Unitree TURN 时：ICE completed，但 DTLS 失败
  → Peer 卡在 connecting，DataChannel 超时
        │
        ▼
修复：Remote 建连前打共享 ICE 补丁
  （同一进程内所有 aioice.Connection 共用一组 ufrag/pwd）
  + Remote 仅用 Unitree TURN（关掉 Google STUN，Clash 更稳）
```

可选对照方案（已验证但能力不全）：

- **仅 DataChannel offer**（不加 audio/video transceiver）：建连极稳，适合只验控制/状态；**没有相机轨**。

### 2.3 点云开关（4G 必开）

与 DimOS `connection.py` 一致：

1. `await disableTrafficSaving(True)`（`execution: ok`）
2. `publish ULIDAR_SWITCH = "on"`
3. `set_decoder("native")`
4. `subscribe(rt/utlidar/voxel_map_compressed)`

`lidar_state` 有数据只说明雷达在转；**不等于**点云 topic 在推。

### 2.4 会话占用

Go2 通常只允许 **一个** WebRTC 控制端。App 后台、上一次脚本未关、连续快重连 → `RobotBusyError` 或假死连接。测试前强制退 App，冷却 20～30 s。

## 五、机器与网络准备

1. Go2 电量建议 ≥ 40%，地面平整空旷。
2. Unitree App 开启公网远程；用手机蜂窝确认顶部 `(4G)`，相机与基础控制正常。
3. **强制退出 App**（划掉后台），等待 20～30 s，释放唯一 WebRTC 会话。
4. 测试中不要再开 App，也不要并行第二个 WebRTC 客户端。
5. 电脑：**不必**连 Go2 AP / 同一 Wi-Fi；可走自己的互联网。
6. Clash：本机验证可保持系统代理；若 TUN 把 `turn.unitree.com` 解析成 `198.18.x.x`，关掉 TUN 或加直连规则。

检查 TURN：

```bash
nslookup turn.unitree.com
# 期望公网 IP（本机曾解析到 121.43.173.60），不要是 198.18/15
```

## 八、DimOS 正式跑 4G

默认 LocalSTA **不变**：

```bash
dimos --robot-ip 192.168.12.1 run unitree-go2
# 或 .env 里 ROBOT_IP + UNITREE_AES_128_KEY
```

### 8.1 4G Remote

```bash
export UNITREE_WEBRTC_METHOD=remote
export UNITREE_USERNAME='你的宇树账号'      # 国内可用手机号
export UNITREE_PASSWORD='你的密码'
export UNITREE_SERIAL='B42D........'
export UNITREE_REGION=cn

dimos --viewer none \
  --unitree-webrtc-method remote \
  --unitree-username "$UNITREE_USERNAME" \
  --unitree-password "$UNITREE_PASSWORD" \
  --unitree-serial "$UNITREE_SERIAL" \
  --unitree-region cn \
  run unitree-go2

# 后台：末尾加 --daemon
```

日志中应出现类似：

```text
Applied shared ICE credentials for Unitree Remote WebRTC
Peer Connection State : connected
Robot Connection Mode : 4G
DisableTrafficSavings: on
FreeAvoid ... ack=True
```

`GO2Connection.start()` 会自动 StandUp → BalanceStand，请保证现场空旷有人看护。

### 8.2 如何确认数据在流（重要）

`dimos topic echo` / 简单 `LCMTransport` 探针在本环境曾出现「收不到」的假阴性。验收请用 **原生 LCM 嗅探**（与 `20260720-dimos-4g-unitree-go2-verify.json` 同一方法）：

```bash
python3 - <<'PY'
import lcm, time, collections
lc = lcm.LCM()
seen = collections.Counter()
lc.subscribe(".*", lambda c, d: seen.update([c]))
t0 = time.time()
while time.time() - t0 < 30:
    lc.handle_timeout(200)
for k in (
    "/lidar#sensor_msgs.PointCloud2",
    "/odom#geometry_msgs.PoseStamped",
    "/color_image#sensor_msgs.Image",
    "/global_map#sensor_msgs.PointCloud2",
):
    print(k, seen.get(k, 0), "Hz~", round(seen.get(k, 0) / 30, 2))
PY
```

本机 40 s 采样结果（`ok: true`）：

| Topic | 帧数 | 约 Hz |
|---|---:|---:|
| `/lidar#sensor_msgs.PointCloud2` | 275 | 6.88 |
| `/odom#geometry_msgs.PoseStamped` | 721 | 18.02 |
| `/color_image#sensor_msgs.Image` | 572 | 14.3 |
| `/camera_info#...` | 40 | 1.0 |
| `/global_map#...` | 55 | 1.38 |
| `/tf#...` | 722 | 18.05 |

`global_map` 有输出说明 **VoxelGridMapper 已吃到 4G 点云**，导航体素链通。

## 九、验收标准（对照表）

### 9.1 连接

- `cloud_login` / SN 已绑定
- `peer_state=connected`，`datachannel=open`
- `robot_network_mode=4G`
- 冷启动连续多次可连（避免快断快连）

### 9.2 控制

- API `code=0` **且** 现场看到站立 / 平衡 / 趴下
- 异常退出应能再次连接，并以 StandDown 收尾

### 9.3 感知与导航数据

- lowstate、odom 持续
- 视频非空分辨率
- 点云：`points_max > 0`，Hz 达到可用（本机 7～9 Hz 量级）
- DimOS：`/lidar` + `/global_map` 有帧

### 9.4 与 Wi-Fi 对照（功能等价，数值不必相同）

| 项目 | 4G Remote（本机） | Wi-Fi LocalSTA | 判定 |
|---|---|---|---|
| 建连 | ~1–2 s，可重复 | 通常更快更稳 | 可连即可 |
| 控制 | 通过 | 通过 | 动作一致 |
| odom | ~18 Hz | 通常更高或更稳 | 不断流 |
| 点云 | ~7–9 Hz | 通常更高 | 格式可进 DimOS |
| 视频 | ~14 Hz，640×360 | 可能更高清 | 可供感知 |
| 电脑上网 / VLM | Clash 可保持 | 同 | 不互斥 |

## 十、常见失败速查

| 症状 | 处理 |
|---|---|
| `RobotBusyError` / SDP reject | 退 App、杀旧进程、冷却 20–30 s；必要时重启狗且不先开 App |
| ICE completed，DataChannel 超时 | 确认用了**共享 ICE**（`nav_acceptance` 或 DimOS remote）；查 fake-ip；避免多客户端 |
| 完整 A/V 失败、dc_only 成功 | 典型 m-line ufrag 问题 → 上共享 ICE，不要只用 dc_only 当最终方案 |
| 点云 0、lidar_state 有 | 查 `disableTrafficSaving` 是否 ok、`ULIDAR_SWITCH=on`、是否 subscribe compressed |
| `dimos topic echo` 无数据 | 改用原生 LCM `subscribe('.*')` 嗅探 |
| 云登录失败 | 国内 `--region cn`；确认 SN 绑在同一账号 |
| LAN 突然要 AES | 那是 LocalSTA 新固件握手，与 Remote **无关**；Remote 不需要 AES Key |
