# Go2 旋转反馈时间戳与零速度执行真机验证报告

日期：2026-07-29
代码版本：`ec19b2fe2`（`jtlinux`）
验证对象：Remote/4G Go2
验证依据：
`jiangtao/plan/2026-07-29-Go2旋转反馈时间戳与零速度执行验证计划.md`

## 结论摘要

1. Remote/4G 的原始 odom `host_rx_ts - source_ts` 不能解释为网络单向延迟。
   两轮各约 10 分钟数据都出现约 10 秒的稳定下沿；它混合了未知的两端时钟
   偏差和最小链路耗时。
2. 固定下沿之上存在可重复但强度变化很大的动态积压。首轮相对 p01 下沿最大
   增加 4.09 秒，复测为 1.13 秒；两轮都能重新回落到下沿。
3. 动态积压主要发生在进入本机 raw callback 之前。两轮本机 WebRTC 事件循环
   延迟最大分别为 26.80 ms 和 19.68 ms，不能解释秒级动态积压。
4. Remote lowstate 实际载荷的 `imu_state` 只有 `rpy`，没有 gyro/yaw speed。
   因此不能直接以陀螺仪角速度确认“零速度命令后机身何时真正停止”，只能用
   rpy 差分、odom 或外部视频交叉验证。
5. 前两次低速尝试因反馈空窗在非零运动前安全终止；复测时 30 秒基线通过，
   完成 47 个低速试次后，0.4 档在显式零命令后继续转动超过 15°安全门而终止。
   0.2、0.3、0.4 的 1 秒脉冲绝对转角中位数分别约为 5.08°、14.57°、22.62°，
   映射明显非线性。
6. 本次不能证明“关闭 lidar 会好转”，也不能证明“完全关闭 lidar 一定无效”。
   低速脚本没有订阅、解码点云，仍复现了 IMU/odom 同时超过 1 秒的反馈空窗，
   说明本机点云订阅/解码不是该空窗出现的必要条件；但连接初始化仍会打开机端
   `ULIDAR_SWITCH`，所以这不是机端 lidar 完全关闭的严格 A/B。
7. 第二轮静止 trace 出现 54 次 source timestamp 按到达顺序回退。所有值均
   唯一，排序后周期正常，且每次回退后立即恢复；这更像 50～107 ms 的消息
   乱序到达，而不是设备时钟本身跳变。未经重排，source timestamp 不能直接
   作为实时反馈顺序。
8. 由于没有设备执行 ACK 和独立外部视频，仍不能把 0.4 的尾转唯一归因于
   机身惯性、零命令延迟应用或历史反馈回放，但控制侧看到的尾转风险已经确认。

## Gate 2：10 分钟 Remote 静止时序

运行：

```bash
uv run dimos --viewer none --navigation-trace-level full run unitree-go2-basic
```

本次不下发运动命令，保持正常相机/雷达数据路径，实际 raw odom 覆盖
611.57 秒。

| 指标 | 结果 |
|---|---:|
| raw odom | 11,370，18.59 Hz |
| raw lidar | 4,509，7.37 Hz |
| WebRTC heartbeat | 6,067，9.92 Hz |
| host-source 时间差 min / p01 | 10.0107 / 10.0176 s |
| host-source 时间差 p50 / p95 / p99 | 10.1992 / 12.3359 / 13.7128 s |
| host-source 时间差 max | 14.1048 s |
| 相对 p01 下沿的最大动态增量 | 4.0872 s |
| source timestamp 回退 / 重复 | 0 / 0 |
| source 间隔 >40 ms 且 host 间隔 <20 ms | 4,860 对，42.75% |
| event-loop delay p95 / p99 / max | 2.01 / 4.46 / 26.80 ms |

时间差在多个区段上升到 13～14 秒，随后又回落到约 10.02 秒。source
timestamp 全程单调，且有大量消息在本机短间隔追赶到达，符合“固定跨时钟下沿
+ 上游动态积压”的特征。

注意：当前 trace 的 source timestamp 语义尚未由 Unitree 官方协议或设备时钟
对时实验确认。因此这里不把约 10 秒下沿称为纯时钟偏差，也不把
`host_rx_ts - source_ts` 称为网络延迟。

### 第二轮复测（20:39）

使用相同 blueprint、full trace 和 Remote 链路再次静止采集 642.72 秒，不下发
运动命令。

| 指标 | 首轮 | 第二轮 |
|---|---:|---:|
| raw odom / 频率 | 11,370 / 18.59 Hz | 12,022 / 18.70 Hz |
| raw lidar / 频率 | 4,509 / 7.37 Hz | 4,872 / 7.58 Hz |
| host-source p01 下沿 | 10.0176 s | 9.9883 s |
| host-source p50 | 10.1992 s | 10.0197 s |
| host-source p95 / p99 | 12.3359 / 13.7128 s | 10.1673 / 10.4769 s |
| host-source 最大值 | 14.1048 s | 11.1224 s |
| 相对 p01 最大动态增量 | 4.0872 s | 1.1341 s |
| source timestamp 回退 / 重复 | 0 / 0 | 54 / 0 |
| event-loop p99 / max | 4.46 / 26.80 ms | 3.32 / 19.68 ms |

第二轮仍支持“约 10 秒固定下沿 + 可恢复动态积压”，但证明积压幅度会话间差异
很大。同时发现：

- 54 次回退中，52 次约为一个 odom 周期（50～60 ms），2 次约为两个周期，
  最大 106.74 ms；
- 回退帧在前一帧到达后的 0.84～9.03 ms 内到达；
- 所有 source timestamp 唯一，按 timestamp 排序后间隔为 50.00～67.65 ms；
- 54 次回退的下一帧全部恢复到正确的时间进度。

因此更准确的结论是“传输/回调观察到乱序交付”，不是已经证明 Go2 source
时钟跳变。实时链路若按到达顺序消费，仍会看到时间倒退，必须丢弃旧帧或设置
有界重排窗口。

## Gate 3：低速脉冲与显式单次零速度

新增独立验证脚本：

```bash
uv run python jiangtao/scripts/validate_go2_rotation_stop.py
```

脚本不导入或调用仓库中的旧标定脚本，遥测采集、原始摇杆发包、安全门和统计
逻辑均为本次独立实现，直接执行以下流程：

- 检查实际 lowstate 字段；
- 30 秒静止噪声基线；
- 计划对 0.2、0.3、0.4，正反方向各重复 10 次；
- 每次非零脉冲后只记录一次显式零速度发送时刻，再观察 2 秒；
- 反馈新鲜度、5 cm 平移和零命令后 15° 旋转均设紧急停止门；
- 退出时发送零速度 burst、趴下并断连。

前两次尝试都在非零运动前安全终止：

- 第一次按 200 ms 新鲜度门运行，静止时已经出现 IMU 212 ms、
  odom 183 ms 的反馈年龄，脚本主动终止。
- 将 200 ms 改为只计数告警、1 秒作为静止阶段硬门后，第二次在静止基线中
  记录到 IMU 1.004 秒、odom 1.013 秒的同时空窗，再次主动终止。
- 实际 lowstate 字段为
  `bms_state, foot_force, imu_state, motor_state, power_v, temperature_ntc1`，
  `imu_state` 下仅有 `rpy`。

### 第二轮低速复测（20:32）

复测的 30 秒静止基线通过安全门：

- IMU/odom 最大反馈年龄为 163.04/136.59 ms；
- 598 次新鲜度检查均未超过 200 ms；
- rpy 差分角速度噪声 sigma 为 0.293°/s，停止阈值取 1.719°/s；
- 电池从 43% 开始，安全退出时为 42%。

完成 0.2 和 0.3 双向各 10 次，以及 0.4 的 7 个完整试次；第 48 个试次为
0.4 反向第 4 次，零命令后的累计转角超过 15°，脚本立即发送零速度 burst、
趴下并断连。

| 摇杆绝对值 | 完整试次 | 1 s 脉冲绝对转角，中位/范围 | 等效脉冲平均角速度中位数 | 零后 2 s 绝对尾转，中位/范围 | 300 ms 静止窗确认 |
|---:|---:|---:|---:|---:|---:|
| 0.2 | 20 | 5.08° / 4.29～5.77° | 约 5.08°/s | 0.21° / 0.01～0.63° | 20/20 |
| 0.3 | 20 | 14.57° / 11.47～16.42° | 约 14.57°/s | 1.11° / 0.05～3.61° | 1/20 |
| 0.4 | 7 | 22.62° / 20.05～25.32° | 约 22.62°/s | 9.20° / 1.99～14.43° | 3/7 |

紧急中止的第 48 个试次没有写入完整 trial，因此表中的 0.4 最大 14.43°不包含
触发安全门的 `>15°` 尾转。

注意：

- “等效脉冲平均角速度”只是本次 1 秒命令窗口内转角/1 秒，不是 Go2 官方
  线性比例。0.2→0.3→0.4 显然不是线性映射。
- 正 `rx` 对应 IMU yaw 减小、负 `rx` 对应 yaw 增大，这是当前 rpy 坐标符号；
  不等同于已经证明左右转控制写反。
- 0.3 的 1/20 静止确认率与较小净尾转并不矛盾：rpy 差分在 2 秒窗口中持续
  出现超过噪声阈值的样本，但缺少外部视频，无法区分真实微动、反馈乱序和
  差分噪声。
- 0.4 的尾转与命令方向一致且量级很大；在根因分层完成前，视觉居中不应使用
  0.4，建议先把运行上限限制在 0.2，并采用单脉冲、显式零、等待新鲜反馈确认
  后才允许下一脉冲。

## H1–H8 判定

| 假设 | 本次状态 | 依据 |
|---|---|---|
| H1 固定时钟偏差 | `INCONCLUSIVE` | 两轮稳定下沿约 10 s，但仍混合未知时钟偏差和最小链路耗时 |
| H2 动态反馈积压 | `CONFIRMED` | 两轮动态增量分别 4.09/1.13 s，均有回落和追赶到达 |
| H3 固定偏差 + 动态积压 | `CONFIRMED` | 两轮均符合 `CLOCK_OFFSET_AND_BACKLOG`，但“固定偏差”严格说是跨时钟下沿 |
| H4 source timestamp 来源/语义不稳定 | `CONFIRMED（消费侧现象）` | 第二轮按到达顺序回退 54 次；证据更指向乱序交付，不是 source 时钟跳变 |
| H5 本机 event loop/解码是主要积压点 | `REJECTED（当前两轮）` | event-loop 最大 26.80/19.68 ms，远小于秒级积压 |
| H6 零命令已执行，仅有制动惯性 | `INCONCLUSIVE` | 0.4 有方向一致的大尾转，但无设备 ACK，不能证明零命令何时执行 |
| H7 零命令未接收或未及时应用 | `INCONCLUSIVE` | 现象与延迟应用相容，但本机 send 完成不等于设备执行，无法单独确认 |
| H8 机身已停但反馈继续追历史数据 | `INCONCLUSIVE` | 已确认反馈积压和乱序，但缺少同步外部视频证明机身先停 |

## 尚未满足的计划项

- LocalSTA 与 Remote 的同场 A/B：当前现场 LocalSTA 服务不可达。
- tracing off/full 的严格性能 A/B：已取得两轮 full，尚无 tracing off 对照。
- Remote 重连、Go2 重启后的 source timestamp 语义对照。
- 0.4 仅完成 7 个试次，第 8 个因 `>15°` 尾转安全中止。
- 设备侧速度命令 ACK 或 Unitree 执行时间戳。
- 外部视频与 IMU/odom 同步，区分机身真转和 odom 回放。
- 从 raw callback 到 decode、TF、controller read、control tick 的同一序列号全链路。

## 建议的下一步

1. 立即把视觉居中的运行旋转上限限制为 0.2；每次只发一个短脉冲，显式发零，
   丢弃/重排倒退的 source timestamp，并等待新鲜反馈确认后再发下一脉冲。
2. 优先恢复 LocalSTA，先做 10 分钟静止 Gate 2，再复测同一低速矩阵。
3. Remote 继续提高旋转幅值前，先加入设备侧或协议侧命令回执；仅有本机
   `send()` 返回时间不能证明 Go2 已执行零速度。
4. 增加外部固定相机，以同一主机 monotonic 时间记录命令、视频、rpy 和 odom。
5. 增加不打开 `ULIDAR_SWITCH` 的连接选项，再对机端 lidar 开/关做相同网络、
   相同时长、相同 trace 配置的 A/B。只有反馈空窗分布显著收窄，才能说关闭
   lidar 有帮助。
6. 保留反馈新鲜度安全门；不要为了拿到旋转结果，把 1 秒反馈空窗当作可接受
   条件继续控制真机。
